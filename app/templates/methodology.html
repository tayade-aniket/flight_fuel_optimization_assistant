📜 Methodology

End-to-end pipeline design, feature engineering, physics baseline, and model selection rationale.

1. Data Sources & Preprocessing

The system uses the EUROCONTROL PRC 2025 Aircraft Fuel Burn Estimation Data Challenge dataset, which fuses two complementary telemetry streams:

  • ADS-B Trajectory Data (OpenSky Network) — 4 Hz sub-second kinematic state vectors: latitude, longitude, barometric altitude, groundspeed, vertical rate, track heading.
  • ACARS Fuel Telemetry (airframes.io) — ground-truth aircraft fuel-on-board (FOB) reports at irregular intervals (every 10–30 min), allowing interval-level fuel burn computation as ΔFOB = FOB_start − FOB_end.
  • Temporal alignment: ADS-B vectors within each ACARS fuel interval are matched using timestamp overlap; sparse intervals fall back to physics-derived feature estimates.

2. Trajectory-Aware Feature Engineering

25 features are extracted per interval, grouped into five categories:

Temporal

duration_min

Vertical / Altitude

mean_altitude_m, mean_flight_level, max/min_altitude, altitude_change_m, altitude_std_m

Kinematic

mean/max_groundspeed_kts, groundspeed_std, mean_vertical_rate_mps, vertical_rate_abs_mean

Spatial

distance_flown_nm/km, track_change_deg_per_min

Phase & Aircraft

is_climb/cruise/descent/approach, ref_mass_kg, nominal_mach, is_narrowbody/widebody/freighter

3. Physics-Residual Hybrid Model

Rather than pure ML, we use a two-stage physics-residual approach:

  1. Stage 1 — Physics Baseline: Estimates fuel burn using the aircraft energy balance: Fuel = (W_drag × Distance + ΔPotential_Energy) / (η × LHV) where W_drag = Weight/L:D, ensuring physical conservation laws are respected.
  2. Stage 2 — ML Residual Booster: XGBoost/LightGBM learns the systematic residuals (aerodynamic non-linearities, thrust setting effects, aircraft aging), capturing patterns the physics model cannot directly compute.
  3. Ensemble: Final prediction = Physics + Residual, guaranteeing non-negative and physically plausible fuel estimates even for unseen aircraft configurations.

5. Constrained Optimization Formulation

The constrained optimizer formulates:

minimize: Estimated_Fuel(FL, Speed)
subject to: FL_min ≤ FL ≤ FL_max (RVSM envelope + aircraft ceiling)
            Speed_min ≤ Speed ≤ Speed_max (aerodynamic limits)
            ΔTime ≤ max_delay_min (schedule constraint)

Solved via exhaustive grid search over RVSM-legal flight levels (FL10 increments) and 9 speed candidates, evaluated using the trained ML model. Pareto frontier is computed over a range of delay thresholds [0, 2, 5, 8, 12, 15] minutes.

6. Limitations & Future Work

  • Wind data not yet fused — groundspeed is a proxy; true airspeed would improve drag modelling.
  • Aircraft weight at interval start is estimated from reference mass, not actual gross weight.
  • Model trained on Apr–Oct 2025 European routes; generalization to other regions may degrade.
  • Future: integrate BADA performance tables for aircraft-specific L/D curves.
  • Future: real-time SIGMET/wind data integration for in-flight advisory use cases.
